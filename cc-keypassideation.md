## Implementation Blueprint — How to Facilitate It

### Core Modules

| Module | Role | Main responsibilities |
|--------|------|------------------------|
| **coffee.key** | User's portable identity | Create, load, sign, scope. Holds username, avatar, public_key. Lives in GitHub JSON. |
| **coffee.distro** | Provider manifest | Manifest generation, verification, "Coffee Seal" status. |
| **coffee.git** | GitHub integration | Read/write public JSON for keys. Uses `coffee.request` or direct fetch. |

---

### Additional Pieces

| Piece | Role |
|-------|------|
| **coffee.pass** | Full identity/vault (or alias for `coffee.key` with full scope). |
| **Schema validation** | Extend `coffee.wire` (or a separate layer) to validate data against a Coffee schema before write. |
| **Session scoping** | Create signed, scoped sessions for distros; they never see the raw key. |
| **Sanitize** | `coffee.sanitize()` to wipe temp data when leaving a distro. |

---

### Implementation Order

1. **coffee.git** — Base for GitHub API (read/write public JSON).
2. **coffee.key** — Uses `coffee.git` for storage; identity creation, loading, signing, scoping.
3. **coffee.distro** — Manifest + verification logic; distro page template.

---

### Flow Sketch

```
User → coffee.key → GitHub repo (public JSON)
Distro → coffee.distro.verify() → manifest check
User visits Distro → coffee.key.scope({ username, avatar }) → signed session
Distro receives session, never sees raw key
User leaves → coffee.sanitize() → wipe temp
```

---

### Design Decisions

1. **GitHub as storage** — Zero infra, but you need auth (PAT, OAuth, or GitHub Apps). `coffee.git` should handle auth.
2. **Distro verification** — Needs a manifest (e.g. `/distro.json` or `/about-coffee`) that can be verified. Verification could be hash-based or signature-based.
3. **Wire schema** — Define a schema for "allowed" data and validate in wire before write.
4. **Session format** — JWT or signed JSON with a short TTL and scoped claims.

---

### The Distro Page (Visible Verification)

A **human-readable page** that every legitimate distro must serve. If a visitor doesn't see it, they know the site is **not** built on the core.

| Requirement | Purpose |
|-------------|---------|
| **URL** | `/distro` or `/about-coffee` — standard, discoverable |
| **Content** | Explicit copy: "This is the Coffee Distro page. This distro is built on the original Coffee Community base + wiring." |
| **Verification** | States that the distro uses the core bricks (que, wire, Control/Drive) as intended |
| **Machine-readable** | Same page (or `/distro.json`) includes manifest for `coffee.distro.verify()` |

**The rule:** No distro page = not built on the core. Visitors can check `/distro` or `/about-coffee` before trusting the site. The page is the "passport stamp" — if it's missing or looks wrong, Hazmat Mode.

**Template:** `COFFEE-SOURCE/COFFEE-DISTRO/distro.html` — Copy to your fork and serve at `/distro` or `/about-coffee`.

---

### Minimal v1 API

- **coffee.git** — `fetch(url)`, `write(path, data)` via GitHub API (with PAT).
- **coffee.key** — `load(githubUser/repo)`, `scope(fields)`, `sign(session)`.
- **coffee.distro** — `manifest()` (returns current manifest), `verify(url)` (fetches and checks manifest), `page()` (returns HTML for the standard distro page).

That gives you a working foundation. Schema validation and sanitize can be layered on top.
